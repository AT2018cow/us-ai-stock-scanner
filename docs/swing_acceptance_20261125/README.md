## 复验及最终签收顺序

1. **先关闭 F01–F04。** 在本地临时账本、模拟时钟、带停牌记录的合成日线和六日历史归档上复跑本文算例，并加入适用测试。阶段 7 的实现摘要随修复变化，应登记新版本。旧协议和结果保留原身份。补齐 G01、G02 后再次运行工作区和干净检出的全量测试。
2. **再签运维与人工工作流。** 在隔离输出根验证带凭证的完整 SIP 扫描及同输入影子开关对照。在实际运行端核对新版自然 cron 的尝试记录、交易日、首次可读时间、指针哈希、日报和周报。随后记录每个应发布交易日，包含失败和漏跑。在真实盘中采集 IEX 个股与 QQQ 的到达时间、时差和降级原因，核对官方归档的前后哈希。事前登记自选、实际阅读和未处理席位，按同周、同行业及同时间预算比较人工复核效率。用新抵达申报验证覆盖恢复数，用同日来源底单验证发现池净增。
3. **最后签经济效果。** 突破和回踩独立登记，保存当时可见的机会、未触发、拒绝和现金，按 5/10/20/60 个交易日自然成熟。10 日主比较至少需 40 个配对交易日、4 个日历块、10 家公司，单一发行人占比至多 25%，配对价格与发布覆盖率分别至少 90%。核对净增量至少 +0.30 个百分点、区块 95% 区间下界大于 0、每边 30 bp 时增量仍正、5% 下尾退化至多 1 个百分点，并看缺价压力和集中度。20/60 日中线采用独立期限及对照。达到预登记条件后再提议调整生产排序。[实验协议](../swing_experiment.md#L128)
