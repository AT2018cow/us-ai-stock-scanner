## 可复现问题

### R01 / P1：负 EBITDA 被解释为优秀杠杆

位置：`src/ai_value_scanner/fundamentals/accounting.py` 的 `derive_accounting_metrics`；`decision/quality.py` 的 `_score_net_debt` 和 v2 balance_scores。

净负债 100，adjusted EBITDA -10，计算得到 -10；Quality v2 输出 `net_debt_to_ebitda_strong=-10`。除法本身正确，经济解释错误：亏损导致的负比率不是净现金。当前只排除 EBITDA=0，而评分把所有 <=0 当最优，并且 >5 的严重风险门无法识别这种情况。

影响已确认到正式 v2 正面证据；未证明真实生产名单中有多少公司受影响，也不声称单个指标必然让公司升级为 A。

建议：比率只在 EBITDA>0 时参与正常杠杆评分；另外保留净现金、净负债和亏损状态。净负债为正且 EBITDA<=0 应明确提示偿债能力风险，不能通过改成 None 后彻底隐藏风险。
验收：覆盖净现金/净负债 × EBITDA 正/零/负的六格矩阵；扫描与历史重建同义；负 EBITDA 不得产生强杠杆证据。

### R02 / P2：NaN 被底层质量评分转成满分

位置：`fundamentals/accounting.py` 的 `clamp01`、`fundamental_quality_score_from_metrics`。

五项输入均为 NaN，输出 1.0。原因是 Python 的 `min(1.0, nan)` 返回 1.0，None 检查不能拦截 NaN。

影响：底层 legacy fundamental_quality_score 不可靠，strategy/rules.py 和 scoring.py 存在消费者。Quality v2 有自己的有限数过滤，不能据此宣称 v2 全 NaN 也得满分。实际生产入口是否可输入 NaN 尚未完成穿透验证。

建议：在数学入口规范化非有限值，缺失值与真实零分分离，并保留覆盖率；不应只在报表层修饰。
验收：None/NaN/正负 infinity 全排列中的异常值均不得增加质量贡献；合法有限数的原有结果保持一致。

### R03 / P2：不完整价格窗口仍输出完整名义波动率

位置：`features/price.py` 的 `compute_price_history_features`。

61 个收盘价中间一个 NaN，其余均为100，输出 volatility_60d=0.0。`np.nanstd` 忽略两项缺失收益率，函数没有记录有效样本数。于是“不知道缺失日波动”被表达成“60日零波动”。

影响确认到特征函数；尚未证明当前行情适配器会放行这种输入。Entry 的 volatility=None 也允许 readiness，因此修复必须同时定义缺失波动率的门禁，不能仅替换统计函数。

建议：验证价格正数、有限性、日期连续性和有效收益率数量，明确缺失窗口的置信度及状态政策。
验收：中间 NaN、首尾 NaN、零价、缺交易日不得静默成为完整窗口统计；缺日检查需要带日期的上游适配层参与。

## 交易研究与工程优化建议（设计建议，非已证实缺陷）

1. **先修语义，再调排名。** 把负盈利、净现金、缺失负债、异常分母、税务和非经营利得建立成独立人工可核算案例。每个案例从原始事实贯通到证据项；避免测试只复述实现。
2. **以人工注意力收益衡量产品。** 在已有不可变快照上统计每周新增候选、重复占位、升级后失效、复核耗时及人工拒绝原因；日榜强调变化，周榜强调质量。先测量，再决定是否增加状态滞回，防止延迟真实恶化告警。
3. **把好公司与价格风险继续分开。** 展示估值假设、盈利正常化敏感性、财报事件及反方证据；不能因为短期强势提高公司财务评级。适用于银行/保险/REIT 的会计解释需独立验证后才能推广。
4. **验证 Entry 的增量价值。** 固定同一 Quality 合格池，比较有无 Entry 的20/60/120日结果，按日期聚合并展示年度、regime、symbol 集中度；重叠标签采用区块或不重叠敏感性检验。先使用冻结证据，不因回测数字漂亮自动推广。
5. **名单压缩加入集中度解释。** 展示候选行业与共同风险暴露，避免十个名字实质上表达同一风险；这属于研究提示，不扩展成自动仓位优化。
6. **统一指标契约。** 每个指标记录分子/分母、单位、符号域、缺失政策、窗口、split/PIT 和版本；共享纯函数保持唯一来源。为共同错误建立跨模块独立数值案例，而非大规模重写已有基础设施。
7. **分开算法置信度和数据完整度。** 记录哪些关键输入缺失、过期或来自推断，让用户知道为何不能比较。IEX 成交额只作为其自身尺度代理。
