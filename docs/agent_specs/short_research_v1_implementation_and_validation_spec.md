- 状态：已实施并完成离线技术复验。生产配置经用户确认开启，冻结回测结论见独立验收记录。

## 1. 目标和交付范围

用已完成交易日的 SIP 行情、当时已知的财务数据和同行估值，识别**公司经营转弱、仍有同行估值溢价、股价相对同行走弱**的候选。首版交付现有扫描中的配置开关、可复用的截面选股函数、最多五只的人工复核名单，以及冻结历史验证。同一次扫描即可生成结果，名单允许为空。

| 扫描输出 | 来源及与主报告的关系 |
| --- | --- |
| Action List（日报和周报） | 主人工复核入口。从预筛候选逐股生成 `StockDecision`，以 Company Quality、Entry Quality 和 Action 状态压缩为各自的多头关注名单。多头详情使用同一批决策。 |
| Low-Value | 并行估值研究清单。可为已有多头决策提供来源背景。 |
| Industry-Trend | 并行产业趋势研究清单。可为已有多头决策提供来源背景。 |
| Momentum | 并行动量研究清单。可为已有多头决策提供来源背景。 |
| Short Research | 第四张并行清单。从同一次扫描的完整预筛特征独立选出做空研究候选。主报告在长名单之外单列同一结果，单独计数，固定最多五只。 |
| Research Pool | 宽口径发现池，保留主题候选等背景信息。继续作为独立的辅助输出。 |

多头 Top-15 的入选、排名、状态、计数和名额与 Short Research 隔离。多头分数、`AVOID`、旧清单的成员和排序均不参与做空筛选。如果同一股票出现于多处，各处照常展示独立证据。同行按 `sic` 分组，ETF 来源仅作发现背景。生产配置下，QQQ 跌破 200 日均线时旧三张清单可同时为空，Action List 仍采用现有防御条件逐股评估，Short Research 仍按自己的条件运行。主报告说明这一关系、各清单状态及文件入口。

使用现有 scan/cron 入口。生产配置开启做空研究，其他配置按各自开关运行。券源标注服务于人工复核。订单、定位申请、账户同步、历史券源库和对冲组合超出 v1 范围。沿用 §4 的做空信号离线比较，用于判断后续研究价值。旧三张清单对 Action List 的收益增量单独立项，本轮无需评估。

### 2.2 特征契约

| 用途 | 必需列 |
| --- | --- |
| 标识与时点 | `signal_date`、`symbol`、`cik`、`sic`、`market_asof`、`fundamental_data_asof`、`market_data_feed`、`watchlist_source` |
| 行情 | `price`、`dollar_volume`、`avg_dollar_volume_20d`、`return_20d`、`return_60d`、`price_to_sma50` |
| 财务和估值 | `revenue`、`revenue_yoy`、`operating_cash_flow_growth`、`operating_cash_flow_growth_direction`、`adjusted_net_income`、`pe`、`shares_stale` |
| 历史评估另需 | `regime`、`fwd_ret_{20,60}`、`label_end_{20,60}`、`qqq_return_{20,60}`、`qqq_label_end_{20,60}` |

- 代码、CIK 和 SIC 按字符串加载，再做显式规范化。合法 ticker `NA` 不可被解析成空值。CIK 须为有效正整数，同一 CIK 的前导零表示应一致。SIC 用四位码，取 `0100` 至 `9999`。有效 OCF 同比方向为 `positive_base`、`reversal`、`both_negative`、`turnaround`。显式解析布尔值，未知的 `shares_stale` 不视作 `False`。
- 缺列、非法信号日、规范化后重复的日期×股票键、混合或未知 feed、未来财报或行情日期均拒绝。逐行缺失、陈旧和非有限值要有理由码。要求 `market_asof == signal_date`，财务比较要求 `fundamental_data_asof` 距信号日 0–180 个日历日，含两端。同日财报沿用上游的时点可用性口径，报告冻结数据只有日期时的限制。全量运行一旦发现数据身份或时点异常，先记录并核实，不能静默屏蔽整类错误。
- 复用 `decision.universe.apply_price_liquidity_prefilter`、`fundamentals.accounting.finite_number`、`features.peer_valuation.compute_peer_relative_valuation`、`evaluation.backtest.holding_session_dates` 和 `research.provenance`。同业估值按短池规则重算，共享现有排名算法。生产分位只用于辅助核对。区块统计可复用现有函数中兼容的部分，完整月历、抽样和缺失处理以本文为准。
- 纯选股函数只接收特征白名单。选择完成后，结算层关联历史结果，展示层关联借券证据。生产 `decisions.jsonl` 和兼容排名 CSV 不保证保存所需的完整截面与特征，不能用于补齐。
- 正式扫描由适配器在 `scanner.py` 内取用共用的预筛截面。`signal_date` 来自已校验的 `sip_eod` 会话，`market_data_feed` 使用实际 feed，`watchlist_source` 用本次底单或发现来源的记录，保留逐股财报和行情时点。已知陈旧行按理由排除并计数，未来日期或数据身份冲突按截面契约处理。历史回放和日常扫描共用 §3 的计算。

## 3. 首版规则

### 3.1 同日可比池

1. **行情基池 (U0)**。要求收盘 `price >= 5` 美元、当日 `dollar_volume >= 2_000_000` 美元、`avg_dollar_volume_20d >= 10_000_000` 美元、必要行情特征有限且 `price_to_sma50 > 0`。要求 CIK、SIC 有效，排除 `6000–6999`，避免将统一 OCF 规则应用于金融、保险及多数 REIT。每个日期同一 CIK 只保留 20 日平均成交额最高的股票，并列按 symbol 升序。先去重，再判断财务。
2. **行业相对强弱**。`rs60_sic = return_60d − median(同日 U0 中其他同行的 return_60d)`。至少四家其他公司，目标股票从趋势同行中排除。`relative_strength_60d_qqq` 可作背景。同行计算先于三组信号。
3. **P/E 溢价**。取 `U0` 中财报时点合格、`shares_stale=False`、`adjusted_net_income > 0`、有限 `pe > 0` 的估值子池。同日同 SIC 至少五家有效公司，含目标。沿用 `rank(method='average', pct=True)`，估值中位数同样含目标。`pe_premium = pe / peer_median_pe − 1`。输出 `pe_peer_count`、`pe_peer_median`、`pe_percentile`。样本不足时分位和溢价应为空，生产缺样本占位值 `0.5` 不表示估值中性。本版只研究正调整后盈利且同业充足的公司。亏损企业的 P/S 或其他倍数以后单独验证。
4. **共同比较池 (U)**。目标须有合格的行业强弱、估值、财报时点、`revenue > 0`、有限 `revenue_yoy > -1` 及带有效方向的有限 `operating_cash_flow_growth`。每层保留排除计数和理由。财务字段完整性是三组共同准入，财务恶化幅度只在 S1/S2 作信号。

### 3.2 三组信号和名单

| 组 | 纳入条件 | 新增证据 |
| --- | --- | --- |
| S0 | (U) 中 `rs60_sic < 0`、`price_to_sma50 < 1.0`、`return_20d > -0.20` | 股价弱于同行并位于 SMA50 下方。已跌20%或更多时标记急跌。 |
| S1 | S0 且 `revenue_yoy <= 0`、`operating_cash_flow_growth <= -0.10` | 营收停滞或下降，且经营现金流同比恶化。使用方向校正的增长字段。 |
| S2 | S1 且 `pe_percentile >= 0.80`、`pe_premium >= 0.25` | 财务、走势转弱后，仍有较高的同行 P/E 分位和显著估值溢价。 |

三组都按 `(rs60_sic 升序, symbol 升序)` 排列。其余特征仅作解释，例如应收和存货增速差、非经营利润、FCF 和波动。本版的均线条件检查当前价位。实际交叉日及反弹失败是后续不同的假设。

逐股显示 `CONFIRMED`（满足 S2）、`WATCH`（财务与估值已满足但走势尚未确认或短期已急跌）、`NO_SIGNAL`（数据合格但研究条件不成立）、`INSUFFICIENT_DATA`（缺关键证据）。价格或流动性等作用域排除以理由码单独计数。名单只列前五只 `CONFIRMED`，其他状态给计数和理由。展示观察值和阈值，以及下次截面复核的失效条件，例如股价重新收于 SMA50 或以上、相对同行转强、经营或估值条件解除。

只读预检只使用特征列。80,531条月度输入中，行情基池约60,115条，共同比较池约19,633条，S2共116条，分布在65个信号日。正式运行以严格解析后的漏斗和有成熟标签的样本为准，并解释差异。

### 3.3 借券证据

默认 `UNKNOWN`，历史回放全部为 `UNKNOWN`。日常扫描可复用本次资产发现已取得的只读券商元数据。仅当来源、环境和网络响应观察时间均可核对，且观察发生在信号日纽约收盘后、报告生成前、距报告生成不超过 24 小时时，才展示已知借券状态。缓存复用仅沿用已保存且仍满足条件的可信观察时点。过期回退、裸缓存、未知字段、冲突及不可核验时点均记 `UNKNOWN`，并记录原因。严禁以运行时间、文件修改时间替代观察时点。复用路径缺少可信证据时允许首版全部显示 `UNKNOWN`，无需额外券商请求。

有效 `shortable=False` 显示「券商显示不可空」，`True` 加确切的 `easy_to_borrow` 显示「券商资料显示易借」，`True` 加确切的 `hard_to_borrow` 显示「需券商确认定位」。报告展示已核实的来源、环境标识和观察时间。v1 中未取得的数量与费率留空，使用前由人工按实际券商条件复核。借券字段只影响展示，三组资格、入选、排序和历史收益样本均不随之变化。参考 [Alpaca 资产字段更新](https://docs.alpaca.markets/us/changelog/2026-06-05-borrow-status-6b96a5a)和 [Alpaca 借券报价及定位说明](https://docs.alpaca.markets/us/docs/margin-and-short-selling)。

## 4. 历史验证

### 4.1 先选成员，再读取标签

1. **同名额归因为主。** 对每个信号日预先冻结各组排序，取共同名额 `k=min(5,n_S0,n_S1,n_S2)`。每组选自己的前 `k` 只，按 `1/k` 等权。保留 `k=0` 日期并单独计数。当 `k>0`，三组用一致日期比较 `S1−S0`、`S2−S1` 和 `S2−S0`。允许名单重叠。另给财务条件的两组诊断，按 `min(5,n_S0,n_S1)` 比较 S1、S0，覆盖 S2 无信号日，独立报告日期和名额。
2. **固定五个名额为辅助。** 每组各取最多五只确认标的，每只权重 `1/5`，空位现金收益为零，整期空仓也是有效现金观察。报告部署比例、空榜率、收益及与同名额结果的差异。`WATCH` 不结算。
3. **主期限20个交易日，60日复核。** 用交易日历和统一 `label_cutoff` 判定成熟。次一计划交易日开盘入场，第 `h` 个交易日收盘平仓。缺入场或结束标签、无日期退市假设、结束日不同于计划、收益非有限、或还原后 `exit/entry <= 0` 均记为缺失。股票端点有效但 QQQ 缺失时仍可比较三组，QQQ 只在端点精确一致时参与辅助对比。组合含任一未知收益则该日期在对应视图的三组完整对比中排除。仍保留所有选中成员、权重和标签状态，禁止替换或归零。对成熟有名额的样本另给缺失槽位统一取空头毛收益 −50% 与 +50% 两种情景，结果是敏感性检验。
4. 按年、上游市场状态和行业分段，保留 `unknown`。2020周频分别报告2–3月和4–6月，2022周频单列。报告名单和收益的公司、行业集中度。按日期配对加权差归属公司，剔除主样本贡献最大的正贡献公司时保留原权重空位，不重新选股。能复用哈希匹配的冻结 SIP 日线与拆股事件时，报告入场至平仓最大不利涨幅 `max(0, max(high)/entry−1)` 及路径覆盖率。缺完整路径时，单独报告期末逆向上涨分布，并登记哪些路径未验证。

`industry_stats.csv` 的收益列按原有名额权重计算各 SIC 对组合的贡献，以对应视图全部完整日期为分母。某个 SIC 无持仓和整组现金日期贡献为零。`ALL` 行与相同频率、期限、视图和组别的总表一致，`active_dates` 记录实际有该 SIC 成员的日期数。

### 4.2 毛收益、成本情景和基准

以入场卖空名义金额为分母，统一使用小数。确认源成本和端点合同后，从有效标签恢复 `x = 1 + fwd_ret_h + 0.003`。其中 `x` 为拆股调整后的 `exit_close/entry_open`，空头毛收益为 `1−x`。QQQ 背景使用同一规则恢复价格毛收益。主基准为同日 S0。同行相对收益辅助表使用同日 (U0) 中其他同 SIC 公司且有有效端点的价格毛收益中位数，同时登记同行可观察数量和缺失比例。至少有四家观察值才算同行相对收益，基准缺失不改变主样本日期。

成本情景使用 `R = 1−x−c×(1+x)−(b+y)×D/365`。每边成交费与滑点 `c` 分别按卖出和回补金额扣除。`D=max(1, exit_date−entry_date 的日历天数)`，`b` 为假设年借券费，`y` 为假设年化股息补偿，v1 以入场本金线性估算。

| 情景 | 每边成本 `c` | 年借券费 `b` | 年股息拖累 `y` |
| --- | ---: | ---: | ---: |
| 仅交易成本 | 15 bps | 0% | 0% |
| 基础假设 | 15 bps | 5% | 2% |
| 压力假设 | 30 bps | 15% | 4% |

三组共享各情景。提供基础参数下的盈亏平衡年借券费 `(1−x−c×(1+x))×365/D−y`，允许为负。结果标记为费用假设下的模拟。真实借券费、股息、召回、停牌和强制回补待有对应历史数据后另行验证。交易费用与股息补偿参考 [SEC 做空说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-51)。

### 4.3 统计与研究结论

- 先算各日期等权组合，再对日期等权。报告毛收益、各成本情景、配对差、下跌命中率、同行相对弱势、尾部和分母。主对比为 **20日 S2 相对 S0 的同名额空头毛收益差**。S1–S0 与 S2–S1 分别解释两项条件的增量。净费后表现及绝对下跌与相对弱势分别披露。
- 月度从原始130个月历位置均匀抽取连续6个月的非循环区块，有放回拼至原长度。重采样2000次，种子 `61122`。保留日期缺失掩码，全空抽样单独计数，使用有效抽样的百分位95%区间。报告配对正增量日期比例。周频用于压力检查，60日和分段作为复核。重叠持有期均值按每期理解。
- 建议判定线在全量结算前冻结。20日共同成熟完整样本少于24个日期、覆盖少于三个自然年，或缺失情景使主配对差或 S2 绝对毛收益变号，判「证据不足」。否则若 S2 绝对毛收益均值、S2−S0 或 S2−S1 的点估计有任一不大于零，判「该信号或增量未通过」，同时保留 S1 的独立诊断。点估计均正，但 S2−S0 区间下界不大于零、仅一个自然年的平均差为正或剔除最大正贡献公司后差值不大于零，判「证据不足」。其余判「支持进入下一轮借券与成本验证」。压力期和成本表现继续披露，第一版结论仅决定是否推进下一轮。
- 实现与研究分开验收。无论经济结论如何，须完整提交规则、评估与证据。事后调整阈值另立协议和运行身份。

## 5. 实施接口和运行

### 5.1 接入现有扫描

1. `config.py` 中的 `enable_short_research` 为严格布尔值，缺省为 `false`。生产配置显式设置为 `true`，沿用 `run_scan.py --config …` 和已有 cron 入口。README 给出使用、状态和文件示例。
2. 在 `scanner.py` 完成共用价格和流动性预筛、量价及财报特征和底单来源合并后，以只读适配后的完整截面调用 `research/short_research_v1.py` 中的 `build_short_cross_section(features)`。取用截面的位置设在旧三张清单和 Research Pool 分流及策略硬筛选之前。保持输入不变，避免按多头财务、名额、QQQ 门槛或主题分数二次裁剪。适配器与离线评估共用选股规则及稳定排序。
3. 显式启用须使用 `sip_eod`、v2 报告版式和调整后净利润口径。配置不匹配时说明哪一项不兼容。正式名单使用完整底单范围。原行情门槛若严于 §3.1 的共用行情阈值，或扫描以 `--max-symbols` 等方式截断同行池，短名单标记为 `unavailable` 并记录原因。逐股缺失按 §2.2 和 §3 计数。复用本次扫描的数据和收盘校验，盘中 IEX 监控不接入短名单。共用 SIP 会话或核心快照校验失败时，继续遵循原有正式发布规则。
4. 研究信号模块分别输出逐股状态、S0/S1/S2 资格、证据和选中记录。评估模块先选股，再结算。报表消费结构化结果。禁止在报告里重算筛选、排序或借券状态，也无需修改 `StockDecision`、长名单源清单映射及已有策略阈值。

### 5.2 输出与快照

启用后，同一会话的快照原子发布 `short_research.json` 和 `short_candidates.csv`。JSON 是本次短名单的记录来源，含合同版本、规则版本、信号日、SIP 身份、运行状态、各层数量、理由计数和有序入选记录。快照 manifest 绑定开关、版本、状态与文件校验值。CSV、日报和周报都由这一份结果派生，使用相同日期、名单顺序与计数。日报、周报在多头名单外放独立的 **Short Research** 区块和相对 CSV 链接。兼容扫描报告只增加状态、计数及实际文件入口，旧三张清单和 Research Pool 的链接及原有输出继续可用。另行记录短名单状态，使日志与兼容报告能区分以下情况。

| 状态 | 解释和产物 |
| --- | --- |
| `disabled` | 开关关闭。沿用已有快照渲染和输出，短名单文件缺省。 |
| `ready` | 筛选成功且有确认候选。CSV 有 1–5 条记录。 |
| `no_candidates` | 完整筛选成功，S2 无候选。CSV 有表头，报告说明筛选完成并展示漏斗。 |
| `unavailable` | 不满足输入契约、范围受限或短名单计算失败。CSV 仅有表头，报告记录稳定的理由码，能计算的覆盖信息仍须保留。 |

CSV 至少包含信号日、名次、symbol、SIC、财报与行情 as-of、60 日收益与同行中位数、SMA50 比值、20 日收益、两项财务变化、P/E 与同行有效数/中位数/分位/溢价、信号状态与理由码、失效条件、借券状态/来源/观察时间。报告保留可推翻当前看法的证据，例如仍为正的经营现金流，以及数据与借券资料的缺口。

在短名单适配、计算或内容生成边界隔离故障。短名单独有的失败以 `unavailable` 继续生成多头结果，借券不可核验时只标 `UNKNOWN`。核心快照原子写入或必需文件校验失败时，遵守现有的失败语义和 latest 指针规则。快照发布后禁止补写短名单文件、更换标签或覆盖当天快照。

同日同策略已有快照时，复用先核对日期、策略风格、行情、现有策略/版式标识及短名单开关和规则版本。身份匹配且快照完整时展示已归档结果，含已归档的 `unavailable`。旧快照缺字段按关闭解释。开关或规则版本不匹配时，提示使用新 `--decision-output-root` 或下一会话，既有快照及其 latest 指针继续保留。为启用版快照登记新的报告渲染修订号，历史修订继续按其合同校验。新版本的校验须识别缺失、篡改、未知版本或状态冲突，校验日期/feed、排序、去重、名额、CSV 和重渲染报告。禁止让校验器从报告提取候选作为权威输入。

### 5.3 实施顺序与复现

1. 实现纯规则、结算与借券展示契约，跑定向单测和逐案手算。
2. 接上现有扫描入口、短名单快照及报告，进行冻结输入启用/关闭对照。在可控的完整截面上通过实际扫描入口生成快照，验证非空、空榜和短名单独有故障。
3. 复用四套冻结数据，先做历史 smoke，再跑完整历史评估。登记短名单筛选与多头隔离的实施结论，以及 §4 的研究结论。
4. 交回验收材料。首轮可用 Mock 的 SIP/SEC 适配器和真实历史冻结截面验证既有入口及计算。若需凭证验证一次真实的完整 SIP 收盘扫描，在独立输出根运行，单独记录已做或待验证事项。

定向及全量测试沿用 unittest。新增 `tests/test_short_research_v1.py`，覆盖现有入口、报告和快照的测试可按其职责放进已有测试模块。

```bash
.venv/bin/python -m unittest discover -s tests -p test_short_research_v1.py
.venv/bin/python -m unittest discover -s tests
```

正式 SIP 发布窗口之前应由现有规则拦截。进入窗口后，凭证试跑使用已有命令。以下复制配置只增加开关并重定向输出。每次独立验收使用新的输出目录。

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path

root = Path("outputs/short_research_v1/qualification")
root.mkdir(parents=True, exist_ok=True)
config = json.loads(Path("configs/config.production.json").read_text())
config.update(enable_short_research=True, output_dir=str(root / "scan"))
with (root / "config.short_research_v1.json").open("x", encoding="utf-8") as handle:
    json.dump(config, handle, ensure_ascii=False, indent=2)
PY

.venv/bin/python run_scan.py \
  --config outputs/short_research_v1/qualification/config.short_research_v1.json \
  --decision-output-root outputs/short_research_v1/qualification/decisions
```

用已有 `scripts/validate_mvp_snapshot.py` 对上述实际生成的日期和策略目录验收。试跑无需预约或提交订单。生产启用前手册说明配置开关、文件位置、停用方式、扫描范围和借券含义。

历史研究仅提供内部可导入入口，例如 `evaluate_frozen_short_research(dataset_root, output_root, *, scope)`。交接提交该入口的实际可复制调用。约定 `smoke` 取月度 `2016-01-29`、`2020-03-31`、`2022-06-30`、`2025-01-31` 的完整截面，`full` 覆盖四套输入。正式历史输出先暂存后一次发布。检查点仅在协议、输入、代码、数据原生成配置及产物身份匹配时复用。历史单日演示从冻结成员中选一例非空与一例空榜，渲染使用同一套规则与输出契约。

仅使用冻结列进行计算时，smoke 可在本地运行。若全量任务较重或需要加载大批冻结原始日线，显式使用 `MODAL_PROFILE=infi`，先用同一代码、配置和输入版本在该环境跑小样本，再前台执行全量，禁止 detach。按实测资源和任务颗粒选择并行度并跟踪进度。记录实际命令、完成状态、耗时和检查点身份。无需重抓 SEC 与行情。
