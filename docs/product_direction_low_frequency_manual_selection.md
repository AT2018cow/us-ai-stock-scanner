# 产品方向：低频、人工决策辅助型选股系统

> 状态：**当前北极星文档（2026-10-10 起）**
>
> 所有 agent 在设计新功能、研究实验、重构输出或安排优先级前，应先阅读本文。
> 当前交接与近期任务见 `docs/work_handoff_after_pr31_20261010.md`。

## 1. 一句话目标

> **先找到值得拥有的公司，再判断现在是不是一个相对合理的买入时点。**

本项目不再以“完备自动量化交易系统”为近期目标，而是构建：

> **低频、人工决策辅助型选股系统。**

系统应把较大的 AI / 科技相关观察池压缩成少量值得人工研究的候选，并把两个问题分开回答：

1. **Company Quality：这家公司是否值得长期关注或拥有？**
2. **Entry Quality：如果公司值得关注，现在是否处于相对合理的介入位置？**

最终交易决定、仓位大小、真实订单和账户管理由人工完成。

## 2. 为什么改变方向

当前仓库最成熟、最值得继续投资的能力是：

- SEC EDGAR 基本面数据获取、清洗与指标计算；
- Alpaca 价格、成交量和趋势数据；
- watchlist / theme / channel 候选池构建；
- 估值、质量、动量、行业趋势和市场状态特征；
- 历史回放、诊断、数据 provenance 和研究证据；
- 把大量股票压缩成人工可复核清单。

一个完整自动交易系统还需要长期维护账户状态、组合优化、订单生命周期、
成交模型、broker 同步、异常恢复、自动调仓和实时风控。这些工作复杂度很高，
却不直接改善“找到好公司”和“找到好位置”这两个核心问题。

因此未来开发优先级集中在：

- 候选公司的基本面质量；
- 进入位置的可解释性；
- 候选列表的精度和稳定性；
- 人工复核效率；
- 数据新鲜度与证据完整性。

## 3. 两层决策模型

### 3.1 Company Quality：值得拥有吗？

这一层变化较慢，应以财务质量、业务质量和估值合理性为主。

优先考虑：

- 收入增长及稳定性；
- 营业利润 / 净利润趋势；
- 自由现金流及现金流转化；
- 毛利率 / 营业利润率趋势；
- ROIC / 资本效率；
- 资产负债表健康度；
- 债务和利息覆盖；
- 股本稀释；
- 应收账款、存货等异常；
- 相对自身历史和同行的估值；
- AI / 产业链相关性及业务质量。

推荐产品语义：

- **Quality A**：高质量，值得重点长期跟踪；
- **Quality B**：质量尚可，需要更多人工研究；
- **Quality C**：当前基本面不足以优先关注。

不要为了提高短期历史收益而频繁改变 Quality 定义。

### 3.2 Entry Quality：现在位置好吗？

这一层变化更快，主要使用量价、趋势和相对强弱信息。

优先考虑：

- 价格相对 SMA50 / SMA200 的位置；
- 20d / 60d 中期动量；
- 趋势斜率；
- 距 52 周高点位置；
- 当前回撤；
- breakout / pullback 结构；
- 成交量扩张或收缩；
- 相对 QQQ 的强弱；
- 相对行业 / 主题篮子的强弱；
- 是否已经过度延伸；
- 大盘 regime。

推荐输出应是人容易理解的状态，而不是只有一个不透明分数：

- **Entry Ready**：位置相对合理，可进入人工买入评估；
- **Watch Pullback**：公司好，但价格偏热，等待回调；
- **Watch Breakout**：基本面达标，等待趋势确认；
- **Trend Damaged**：趋势结构被破坏；
- **Overextended**：过度延伸，不宜追高。

这些状态是研究提示，不是自动交易指令。

## 4. 最终面向用户的核心产物：Action List

**Action List 是项目最终面向用户的核心产物。**

项目不应以“多张策略列表 + 大量指标表”为主要用户体验，而应把用户有限的注意力分配到最值得继续研究的少数公司上，明确回答：

> **今天 / 本周该看谁、为什么、现在该做什么研究、下一步等待什么。**

### 4.1 Action List 的核心分组

建议最终输出至少包含：

- **Buy / Entry Ready**
  - Company Quality 强；
  - Entry Quality 合理；
  - 没有明显追高、趋势破坏或基本面红旗；
  - 含义：优先进入人工买入评估，不代表系统自动买入。

- **Watch Pullback**
  - Company Quality 强；
  - 趋势仍健康，但当前位置偏热或过度延伸；
  - 含义：公司值得拥有，但当前价格不值得追。

- **Watch Breakout**
  - Company Quality 达标；
  - 趋势尚未确认，等待突破、相对强弱或成交量确认；
  - 含义：提前关注，但不抢跑。

- **Hold / Monitor**
  - 公司质量和趋势没有明显恶化；
  - 当前没有新的高质量入场信号；
  - 含义：对已研究 / 已持有标的保持观察，不暗示自动持仓管理。

- **Avoid / Deteriorating**
  - 基本面恶化、趋势破坏、价格过度延伸，或关键数据不足；
  - 含义：降低研究优先级，并明确说明原因。

名称未来可以调整，但语义必须简洁、稳定、可解释。

### 4.2 每只股票最少应显示什么

Action List 中每个候选至少包含：

- symbol / company；
- **Company Quality 等级**；
- **Entry Quality 状态**；
- **Action State**；
- 2–4 个最重要的正面理由；
- 1–3 个最重要风险 / 反对理由；
- 当前价格结构的简洁解释；
- 触发升级 / 降级的关键条件；
- 关键数据 as-of / freshness；
- provenance / 计算版本；
- 与上一次相比是否发生状态变化，以及变化原因。

主输出的目标不是“展示系统知道多少”，而是帮助用户快速决定下一步人工研究。

### 4.3 输出规模

主 Action List 应尽量短。

工程上可以把：

> **每次约 5–15 个真正值得重点人工复核的名字**

作为产品输出规模目标，而不是硬性交易数量。

可以保留更宽的 secondary watchlist / research pool，但不能让它们淹没主 Action List。

### 4.4 Daily 与 Weekly

**Daily Action List**

- 更新 Entry 状态；
- 只突出新增候选、状态升级 / 降级、重大价格变化；
- 基本面无变化时不重复制造噪音。

**Weekly Review List**

- 更完整地重新排序 Quality × Entry；
- 回顾一周状态变化；
- 纳入新财报、新的基本面风险和需要人工深挖的公司；
- 作为主要人工研究工作台。

“每天生成”不等于“每天交易”。

## 5. 详细报告：Action List 的证据层

Action List 负责决策压缩；**详细报告负责解释、审计和深挖**。

用户从 Action List 进入某只股票后，应能看到结构化详细报告，至少包括：

### 5.1 Company / fundamentals

- 最近可用财报及 filing as-of；
- 收入、利润、FCF 趋势；
- 利润率趋势；
- 资本效率；
- 资产负债表和债务；
- 稀释；
- 估值及历史位置；
- 异常项 / 缺失项；
- Company Quality 形成原因。

### 5.2 Entry / market structure

- 当前价格与 SMA50 / SMA200；
- 20d / 60d momentum；
- 52 周位置和回撤；
- breakout / pullback 结构；
- 成交量变化；
- QQQ / 行业相对强弱；
- regime；
- overextension / trend damage；
- Entry State 形成原因。

### 5.3 Risks and counter-evidence

详细报告不能只展示支持结论的证据。必须同时列出：

- 最大基本面风险；
- 最大估值风险；
- 最大技术面风险；
- 数据陈旧 / 缺失；
- 可能导致 Action State 改变的条件。

### 5.4 History

可选但重要的增强：

- Quality 历史等级变化；
- Entry State 历史变化；
- Action State 变化；
- 变化日期和原因；
- 当时已知数据的 provenance。

**Action List 与详细报告必须来自同一套底层判断。**
不能出现主清单说“Entry Ready”，而详细报告使用另一套逻辑得出相反结论。

## 6. Quality × Entry 统一矩阵

长期用户界面应围绕二维框架，而不是多张彼此竞争的策略列表。

| Company Quality | Entry 弱 | Entry 中等 | Entry 强 |
|---|---|---|---|
| **A** | Watch / 等待 | Watch Pullback / Breakout | Buy / Entry Ready |
| **B** | 低优先级 | Hold / Monitor | 战术候选，需更多研究 |
| **C** | Avoid | Avoid | 通常不追 |

Action State 应由简单、可审计的规则产生。复杂模型可以提供证据，但不要让最终状态变成黑箱。

## 7. 低频原则

本项目不追求高换手。

推荐节奏：

- SEC / 基本面：新财报出现时刷新，日常可缓存；
- Company Quality：周度或财报事件驱动重新评估；
- Entry Quality：交易日更新；
- Daily Action List：每日生成，但只突出有意义的状态变化；
- Weekly Review List：每周完整复核；
- 研究复盘：月度或季度。

系统价值应来自少量高质量决策，而不是增加交易次数。

## 8. 现有列表如何迁移

现有 `low_value`、`momentum`、`industry_trend` 和 `research_pool`
不需要立即删除。

它们逐步从“彼此竞争的最终产品清单”转为新框架中的证据来源：

- `low_value`：估值、质量和价值陷阱过滤经验；
- `momentum`：Entry Quality、相对强弱和趋势证据；
- `industry_trend`：行业 / 主题相对强弱和确认信号；
- `research_pool`：宽口径发现层。

长期产品输出围绕 **Quality × Entry → Action List → Detailed Report** 统一。

## 9. 明确的非目标

当前路线不以以下事项为目标：

- 自动连接券商下单；
- 自动调仓；
- 高频或日内交易；
- 完备账户级 NAV 模拟；
- 最优仓位模型；
- 复杂组合优化；
- 为追求历史收益进行大规模参数搜索；
- 把所有判断压进一个 composite score；
- 为了“量化完整性”开发与人工选股价值无关的基础设施。

现有 portfolio / live-pilot / trade-plan 研究可以保留为历史证据或未来可选工具，
但不再定义当前研发主线。

## 10. 研发优先级

### Stage 1 — 定义统一输出契约

先定义一只股票最终应输出哪些字段：

- Quality grade / score；
- Entry state / score；
- Action state；
- 关键基本面理由；
- 关键价格理由；
- 风险项；
- provenance / freshness；
- 状态变化原因。

同时定义 Action List 与 Detailed Report 的共同数据源和一致性契约。

### Stage 2 — Company Quality baseline

重点复用已有 SEC 基础设施。

优先目标：

- 指标定义正确；
- PIT / freshness 清晰；
- 结果可解释；
- 对异常财务结构不脆弱；
- 能稳定把明显弱公司降级。

先验证排序和分层，不追求精确预测未来收益。

### Stage 3 — Entry Quality baseline

复用 momentum / industry_trend / regime / technical 特征。

重点识别：

- 健康趋势中的合理介入；
- 过度延伸；
- 趋势破坏；
- 回调后的再确认；
- breakout 前后的状态变化。

不要把短期涨幅简单等价为“好位置”。

### Stage 4 — Action List + Detailed Report

把 Quality 和 Entry 合并成少量人工可执行状态。

主列表保持紧凑；详细报告提供完整解释和反方证据。

### Stage 5 — prospective observation

冻结版本后持续记录：

- 当时的 Quality；
- 当时的 Entry；
- Action State；
- 当时的详细理由和风险；
- 后续 20 / 60 / 120d 表现；
- 状态变化；
- 人工复核备注。

重点验证系统是否提高人工研究命中率和效率。

### Stage 6 — 可选交易 / 组合工具

只有当人工选股流程已经稳定，而且真实使用证明需要时，才考虑：

- 简单持仓记录；
- 风险预算；
- portfolio NAV；
- broker integration；
- 自动执行。

这些都是可选扩展，不是当前成功定义。

## 11. 研究标准

新方向仍保留严格研究纪律：

- retrospective 与 prospective 明确区分；
- 不用未来数据污染当时判断；
- 保留输入、代码和配置 provenance；
- 基本面指标必须处理 filing 时点；
- 技术信号使用当时可获得价格；
- 评价时按 signal date 聚合，避免把重叠 forward labels 当独立样本；
- 报告年度 / regime / symbol concentration；
- 不因一次漂亮回测就提升生产等级；
- 优先简单、稳定、可解释的机制。

评价目标从“能否构造自动赚钱组合”转为：

> **是否能稳定把有限的人工注意力放到质量更高、位置更合理的公司上。**

## 12. Agent 开工检查

开始一个新任务前，至少问：

1. 这个工作提高 Company Quality 判断了吗？
2. 这个工作提高 Entry Quality 判断了吗？
3. 这个工作让 Action List 更短、更清楚、更有用了吗？
4. 这个工作让 Detailed Report 更可解释、更可审计了吗？
5. 这个工作提高数据正确性、新鲜度或 provenance 了吗？
6. 如果以上都不是，为什么现在值得做？

如果主要理由是“这样更像完整量化交易系统”，默认不做。

## 13. 当前成功定义

当前阶段项目成功，不要求自动交易或完整账户回测。

成功意味着：

1. 能从观察池中稳定找到财务质量较好的公司；
2. 能把“好公司”和“好买点”分开判断；
3. 能识别追高、趋势破坏和等待确认等不同状态；
4. 每次只给少量真正值得人工研究的候选；
5. **Action List 成为日常核心工作台**；
6. **Detailed Report 为每个候选提供完整支持证据与反方证据**；
7. 数据来源、新鲜度和计算逻辑可审计；
8. 前瞻观察显示这些提示对人工研究有实际帮助；
9. 系统本身不替用户做最终交易决定。

这就是当前项目的北极星。
